# 0003: i18next for EN and ID

Status: Accepted (2026-09)

## Context

The UI follows the browser language (English, Indonesian) and must never show a raw key. Product terms
(Box, Tab, Card, Quick Bar) stay in English in both languages (glossary G5).

## Decision

`i18next` with `react-i18next`, resources bundled (`src/i18n/en.json`, `id.json`), no lazy loading and no
backend. In test mode a missing key throws. A unit test asserts that both files hold the same keys and an e2e
test renders the Indonesian UI and checks for raw keys.

## Alternatives considered

- Lingui: smaller runtime and compile-time extraction, but message extraction needs a Babel/SWC macro step and
  ICU plural rules for Indonesian (only `other`) give no advantage. Not chosen.
- A tiny custom `t()` function: no plural or interpolation escaping, and every later feature would rebuild parts
  of i18next. Rejected.

## Consequences

- i18next and react-i18next add about 20 KB gzip. Accepted.
- Indonesian uses only the `_other` plural form.
